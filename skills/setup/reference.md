# Setup reference - optional tools

Facts come from the tune-up install research (Claude Code 2.1.x, tool versions of that date). Anything that research could not confirm is marked `[unverified]`. Versions move fast: read the real output of the check commands, do not assume.

Legend: **Interactive = no** -> the skill may run it through Bash (each call still asks permission). **Interactive = yes** -> the user types it with `! command` (or in their own terminal); the skill never runs it.

## Prerequisites (check only)

| What | Check | Needed for |
|---|---|---|
| Claude Code | `claude --version` | 2.1.274+ for fast-jev function hooks |
| Node | `node --version` | 20+ for claude-mem; Caveman and Ponytail hooks need `node` in PATH |
| uv | `uv --version` | Graphify install (`pipx` also works) |
| git | `git --version` | ECC marketplace clone |

## Notes

- `claude plugin list --json` output shape: read it once and match ids; the field names were not inspected `[unverified]`.
- Re-installing ECC may turn it back on `[unverified]`; always re-run `claude plugin disable ecc@ecc` after an install. Never list ECC under `dependencies` (a dependency cannot stay disabled).
- `install ... --config` and `configure --values-stdin` exist in `claude plugin ... --help`. Running `configure` from a Bash call inside the session is not used for secrets.
- Plugin output style value for `/output-style`: shown as `tune-up:caveman-summary` `[unverified]` - ask the user to pick it from the list.
- New plugins work only after `/reload-plugins` or a new session; an `env` change in settings needs a restart.
- tune-up profile: `~/.config/tune-up/user.json`. Undo: delete the file (defaults apply again).
