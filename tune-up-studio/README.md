# tune-up-studio

Status: work in progress. A plugin of the `tune-up` marketplace that depends on
`tune-up` (it adds a module to its panel):

```sh
claude plugin marketplace add stage2dev/tune-up
claude plugin install tune-up@tune-up
claude plugin install tune-up-studio@tune-up
```

Platforms: the studio runs on macOS, Linux and WSL2 only. Native Windows is not
supported (the Claude Code sandbox it relies on does not run there); the
`tune-up` panel itself still runs on Windows.

## Turn it on in a project

The panel loads nothing from a plugin unless the project names it. In the
project's `painel.json`:

```json
{
  "modulos_de_plugins": ["tune-up-studio@tune-up:estudio"],
  "acoes_de_plugins": ["tune-up-studio@tune-up"],
  "estudio": {"video_rede_local": false}
}
```

- `modulos_de_plugins` adds the Estudio screen; `acoes_de_plugins` adds the
  `estudio.*` actions.
- The first time, and after every plugin update, the panel pins the plugin's
  version and sha256 and refuses it until you confirm in a terminal:
  `python3 painel.py --aceitar-extensao tune-up-studio@tune-up`.
- `estudio.video_rede_local: true` turns on the render action
  (`estudio.video-motion`). It lets the page being rendered reach localhost and
  the machine's LAN address on macOS, so it is off by default; without it,
  videos come from the FFmpeg slide reserve.
- Then open the Estudio screen and follow its steps: Ambiente, Marca, Novo.

## What it is

A studio module for the `tune-up` panel that turns a project's brand source of
truth into finished pieces: a still post (4:5, 1080x1350 PNG) and a silent
vertical reel (9:16, 1080x1920, 10 s MP4). Compositions are HTML written from
scratch (CSS `@keyframes` only, no GSAP, no network), rendered locally with a
pinned [HyperFrames](node/README.md) 0.9.6, then judged by deterministic QA
scripts. If HyperFrames is missing or fails, the reel is built from slide PNGs
with FFmpeg (`scripts/video_ou_reserva.py`).

Business photos: the owner uploads them on the Marca tab (`fotos` in
`marca.json`, the first is the main photo). A post, reel or ad may use up to 2 of
them; `scripts/fotos.py` copies them (and a PNG/JPEG/WebP logo) into the piece's
`fonte/assets/`, so the session never reads image bytes or names a source path.
A photo is shown with `object-fit: cover`; text always sits on a solid brand-color
band or block at 4.5:1 or more, never directly on the photo. A Google Search ad
image stays clean: with a main photo it is that photo alone, no text, no logo.
The QA (`qa_imagem.py`, `qa_video.py` and the panel badge) accepts images only
from `assets/` inside the source (png, jpg, webp by their bytes, plus
`logo.svg`); no image is ever generated by AI.

The proof project is a fictional bakery in `exemplos/forno-miudo/`. Piece
text in the example is Brazilian Portuguese; code and docs are English.

## Requirements

Measured on macOS (10 cores, 16 GB):
Node v26.5.0, FFmpeg 8.1.2 (with `ffprobe`), Python 3.9+ (standard library
only), headless Chrome in `~/.cache/hyperframes/chrome`. Linux and WSL2 are
planned; they are not verified here. On Linux the sandbox also needs `bwrap`
and `socat`.

Check a machine (report in Brazilian Portuguese, exit 1 if something is
missing or blocks):

```sh
python3 -I tune-up-studio/scripts/verificar_ambiente.py --projeto <project folder>
```

It checks the OS, Node >= 22, the pinned HyperFrames install, the
chrome-headless-shell version HyperFrames 0.9.6 pins in its cache, ffmpeg and
ffprobe with every filter and the encoder the scripts use, `bwrap`/`socat` on
Linux, and the sandbox lists in the user, project and managed settings that
merge into the studio's: `excludedCommands` and `network.allowedDomains` block,
`filesystem.allowWrite` warns.

## Safe install

```sh
cd tune-up-studio/node
npm ci --ignore-scripts        # lockfile pinned, integrity hashes, no install script
```

Run every HyperFrames call with:

```sh
export HYPERFRAMES_NO_TELEMETRY=1 DO_NOT_TRACK=1 HYPERFRAMES_NO_UPDATE_CHECK=1 \
  HYPERFRAMES_NO_AUTO_INSTALL=1 HYPERFRAMES_SKIP_SKILLS=1
npx --no-install hyperframes <command>
```

Never run: `cloud`, `lambda`, `tts`, `transcribe`, `skills`, `upgrade`, `add`,
`browser`, `snapshot --describe`, `render --docker`, or `init` with a template
(templates load GSAP from a CDN). See `node/README.md` for the pin and the
known `undici` audit finding. `regras/bash-estudio.json` is the hook
positive list that enforces this for studio actions.

## Commands

| step | command (from `tune-up-studio/node`) |
| --- | --- |
| still | `hyperframes snapshot <fonte> --at 0 --no-end -o <OUT>` |
| strict check | `hyperframes check <fonte> --json --strict > check.json` |
| render reel | `hyperframes render <fonte> -o <OUT>/video.mp4 --fps 30 --quality delivery` |
| QA still | `python3 -I scripts/qa_imagem.py --source <fonte> --png <png> --check-json check.json --out qa.json` |
| QA reel | `python3 -I scripts/qa_video.py --source <fonte> --video <mp4> --out qa.json --sheet folha.png` |
| reserve reel | `python3 -I scripts/video_ou_reserva.py --source <fonte> --slides <png dir> --out <mp4>` |
| ad sizes and limits | `python3 -I scripts/anuncio.py --plano google` |
| ad sheet (all Paused) | `python3 -I scripts/anuncio.py --exportar <work folder> --plataforma google` |
| ad final QA | `python3 -I scripts/anuncio.py --final <work folder> --plataforma google --out final.json` |

Details, the check list and the measured behavior of CSS-only animation are in
`scripts/README.md`. Tests (no Chrome, no network): `python3 -m unittest
discover -s tests` from `tune-up-studio/`.

### Real actions `estudio.video` and `estudio.video-motion` (PROVISIONAL, 2026-11-11)

Two actions, one skill (`skills/video`). `estudio.video` makes the reel from
still slides of the composition (`snapshot` + `reserva_slides.py`), so it needs
no local port and runs with plain `"sandbox": true`. `estudio.video-motion`

### Real action `estudio.anuncio` (PROVISIONAL, 2026-11-11)

One skill (`skills/anuncio`), one deterministic script (`scripts/anuncio.py`).
The form asks for the briefing, the platform (`google` or `meta`) and the
landing URL (the panel refuses anything that is not `https://` without spaces).
The session makes one master image and the adaptations the platform needs
(Google: 1.91:1 1200x628 and 1:1 1200x1200 from `google-ads-pmax-imagem`;
Meta: 4:5 1440x1800 and 9:16 1080x1920), each rendered and checked by
`qa_imagem.py` at its own size. Google pieces carry no text, logo or `<img>`
(the subject is an inline SVG drawing): the sheet makes a Search campaign, and Google rejects Search image assets
with overlaid text or logos; the owner adds the PNGs as image assets after the
import (they are not in the sheet). On the 9:16 Meta piece every text sits in
`#safezone` (top 14% and bottom 20% free, clipped); it is not in the sheet and
goes up by hand on Stories/Reels. `anuncio.py --final` and the server seal
check both rules statically from `index.html`. The session writes
`textos.json` and runs
`anuncio.py --exportar`, which checks counts, lengths, required fields and the
URL, and only then writes the sheet. The script never judges claims: the skill
forbids promises of results and prices that are not in the briefing. Nothing
is published, no ad API is called, nothing is spent.

- `export/google-ads-editor.csv`: one campaign row (Search), one ad group row
  and one responsive search ad row, all `Paused`; names come from the work id.
  No budget column and no keyword is filled: set them in the Editor.
- `export/meta-experimental.csv`: EXPERIMENTAL. Column names and status values
  were not checked against an official Meta source; every status is `PAUSED`
  and the image column names the master PNG. The 5-variation cap is ours, not
  a Meta number.

**The Google Ads Editor CSV format is NOT confirmed by an official source.**
The research read the Editor help page (import only stages local drafts;
nothing goes live until "Post"; `Status` accepts `Paused`; English headers),
but not the exact column names, encoding or the rows a new campaign needs. The
columns used (`Campaign`, `Campaign Status`, `Ad Group`, `Ad Group Status`,
`Ad type`, `Status`, `Headline 1..15`, `Description 1..4`, `Path 1..2`,
`Final URL`) are an assumption. Criterion C12 (the owner imports the CSV in
the Editor and sees a paused draft) **depends on the owner's test**.

The server seal re-checks every piece at its planned size, the texts against
the limits and the URL the owner typed, and that the sheet is byte for byte
the one `anuncio.py` makes from `textos.json` (so it is all `Paused`). Approval
copies the PNGs and the sheet; `manifesto.json` lists the sheet under
`export` with its sha256, plus the texts, `experimental` and
`publicado: false`. The Approval tab shows the texts before approving and,
once approved, a download link: the media route serves `.csv` only from
`aprovados/` (the module's `INFO["baixar"]`) as `text/csv` with
`Content-Disposition: attachment`.

Measured by `painel/tests_reais/prova_anuncio_bg.py` (same harness as the
post), model **opus**, one machine (macOS). The first row is the Google run
before clean images were required (its pieces had text over them):

| piece | wall clock | turns | tokens (input / cache creation / cache read / output) | QA final line | fix rounds |
| --- | --- | --- | --- | --- | --- |
| ad, Google, 2 images + 15 titles + 4 descriptions | 369 s (idle from 189 s; the harness waits for the transcript to go quiet) | 10 | 18 / 86,535 / 662,586 / 9,472 (758,611) | `PRONTO: 2 de 2 pecas verdes, textos e planilha ok` | 1 (1:1 piece) |
| ad, Google, clean images (inline SVG, no text) | 157 s | 11 | 21 / 55,336 / 731,760 / 10,047 (797,164) | `PRONTO: 2 de 2 pecas verdes, textos e planilha ok` | not counted |
| ad, Meta, 4:5 + 9:16 with `#safezone` | 351 s | 12 | 22 / 66,984 / 867,572 / 10,219 (944,797) | `PRONTO: 2 de 2 pecas verdes, textos e planilha ok` | not counted |

## Proposed caps per action (PROVISIONAL, to be revised in Parts 5 and 6)

These are proposals set from the table, not enforced yet. The time cap is the
only one the panel can enforce (`max_minutos`, plan item 1.6); the others
must be stated in the action prompt and checked by the QA scripts or the
hook.

| cap | proposal | basis |
| --- | --- | --- |
| pieces per request | 6 (for example 4 posts + 2 reels) | Rendering is not the limit: 6 reels would take about 30 s of render. The limit is model tokens, which are not measured, so this number is a guess that keeps one session small. |
| correction rounds per piece | 2 | Plan rule. A third round is a stop, the piece is reported as failed with the QA findings. |
| `max_minutos` | 15 | Render plus QA for 6 pieces is under 1 minute on the measured machine; the rest is model time, not measured. 15 leaves room for 2 rounds on 6 pieces. Raise only with a measured run. |
| `max_bloqueado_min` | 5 | Guess: a session waiting on a permission prompt should not hold a slot. Not measured. |
| concurrent studio actions | 1 | Peak RAM of one reel render is about 0.5 GB for its largest process and the reserve path reached 0.9 GB. |

Parts 5 and 6 measure again with the real action and replace this section.
`estudio.post` already applies `max_minutos` 15 and `max_bloqueado_min` 5.
