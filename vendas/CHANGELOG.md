# CHANGELOG - tune-up-vendas

## 0.3.0 (unreleased)

- One-step setup `servico/preparo.py` (`rodar`, `iniciar` detached, `estado` as JSON; helpers `preparo_sistema.py`, `preparo_docker.py`, `preparo_evolution.py`): five resumable steps that check before acting - find or install Docker (macOS `brew install colima docker docker-compose`, Windows `winget` Docker Desktop, Linux and a missing Homebrew = a command for the owner to paste, never `sudo`), start Docker (`colima start`, Docker Desktop) with a bounded wait, prepare the Evolution files (never `--refazer`, existing `.env` untouched, a taken default port replaced by a free one), `compose pull` + `up -d` and wait for the Evolution on `127.0.0.1` (never `down` or volume removal), and start the sales service detached and wait for its `/saude`. State `preparo.json` and log `preparo.log` (0600) in the external data folder with per-step state, plain pt-BR message and command; one run per project (`preparo.trava`), a dead run is `interrompido` and the next run resumes; the Evolution key and Postgres password are masked everywhere. `travas.TravaDoProcesso` takes an optional lock file name.
- Setup review fix: the Evolution counts as running only when `GET /instance/fetchInstances` with the `.env` key answers 200 (before, any HTTP 2xx-4xx on the port did, so another program on that port ended the setup as done without starting the Evolution). Another program answering on the port without accepting the key is `precisa_do_dono` with a command to see which program it is; the wait after `up -d` uses the same authenticated call. `Sistema.http` takes optional headers.

## 0.2.0

- Inbox with media: the Conversas tab shows lead audio (player, transcription under it), images and documents through the panel (`arquivo(ctx, ref)` in the module, refs `m:<id>` only, bytes read from this project's service with a size cap, the service token never leaves `cliente.py`). Each media message carries state (pronta, pendente, falhou, expirada), a plain pt-BR notice and, for a failed download, the closed action `midia_baixar_de_novo` (`POST /midia/<id>/baixar-de-novo`). The list preview reads "Áudio (0:12)" with the first words of the transcription, "Foto" or "Documento: name.pdf" (`GET /conversas` adds `ultima_duracao_s`, `ultima_nome`, `ultima_transcricao`). The IA tab states that transcription and image reading count in the daily cap. README section "Áudios, imagens e documentos".
- Media hardening from the review: the download worker survives errors (a locked database included) and logs only the exception type; a dead worker is restarted on the next enqueue, or the row fails with `sem_baixador` while the service stops. A file whose `pronta` update fails is deleted, and at start `.tmp` leftovers and files without a row are removed. A webhook with the wrong secret stores no media key and cannot be downloaded again (409); the Conversas tab offers no retry for failures that would repeat (`sem_segredo`, `grande_demais`, `tipo_recusado`, `expirada`). An Evolution 400 is `expirada` only when the body says so; other 400s get the short retry. `ffprobe` gets the detected format (`-f`). Migration 20: `midias.falha_ia` (a failed transcription or a refused image is not retried or paid again automatically; later texts are answered and the conversation stays "precisa de você"; the owner's "Tentar de novo" clears it and gives the AI its turn only if no message went out after that file) and `envios.fala`. Only the API's real no-vision error is `modelo_sem_visao` (other 400s with an image: `imagem_recusada`). Spoken/captioned opt-out is screened in every available transcription and caption, also after an earlier media failed and in a paused conversation (switch on), which is now marked "precisa de você" (`pausa_humana`); in human mode the audio is never transcribed (nothing goes to OpenAI). Stopping the service during the wait is not `midia_indisponivel`; the transcription's missing price is `preco_transcricao`. Module: `arquivo()` raises on 403/500/3xx from the service (panel 500, not a silent 404), refuses a body shorter than `Content-Length`, and the module's HTTP opener no longer follows redirects (the send token never goes elsewhere). The list preview keeps image/document captions and the spoken text of the AI's voice note.
- Module `arquivo()`: only a malformed ref or a 404 from the service is "not found"; a stopped service, a service of another project or one that does not answer in time (`cliente.Recusa`) now raises, so the panel answers 500 instead of a silent 404 (5xx, 403, 3xx and truncated bodies already did).

## 0.1.0

- Plugin skeleton: manifest, license, README, a panel module `vendas` with one tab ("Conexão") that says the service is not running, and tests. No WhatsApp code yet.
- Service storage: `servico/pasta.py` (data folder outside the project, refuses a folder inside the project root or under a synced folder with `.stfolder`/`.stignore`; 0700/0600 on POSIX), `servico/banco.py` (SQLite WAL, migrations by `user_version`, unique `id_externo`, partial unique `chave_dedupe` that ignores `negado`) and `servico/telefone.py` (Brazilian 9th-digit variants, rejects `@lid`).
- Local service `servico/servico.py` (+ `rotas.py`, `travas.py`): `127.0.0.1` only, one process per project (non-blocking lock, POSIX `flock` / Windows `msvcrt`), send token per start (0600), `GET /saude`, `GET /token-de-envio` only for the exact panel origin, token-protected `GET /estado`, `POST /webhook/<instance>` with a header secret (modes `registra_e_conta` and `recusa`, counters in the database, raw event stored), heartbeat every 3 s, clean stop on SIGINT/SIGTERM. The screen reads the heartbeat read-only and shows "Serviço rodando" or "Serviço parado" with the start command.
- Connectors `servico/conectores/`: `base.py` (the `Conector` interface and two errors, `NaoEnviado` = surely not sent, `EnvioIncerto` = may have been sent), `evolution.py` (Evolution API v2 over urllib; URL and key from `VENDAS_EVOLUTION_URL` / `VENDAS_EVOLUTION_CHAVE`; registers the webhook URL with the secret header on create; no proxies, no redirects; never disconnects or deletes the session; webhook translation for text, audio, image, document, group, `fromMe` and `@lid` with `remoteJidAlt`/`senderPn`) and `falso.py` (in-memory fake that can accept, refuse, accept-then-drop or time out).
- Send gate `servico/portao.py`: one function per origin (`manual`, `rascunho_aprovado`, `ia`, `campanha`, `audio_ia`, `teste_audio`, `confirmacao_sair`) applying the origin x rule table (opt-out, human pause, 09-19 window in the project time zone, 8/min and 200/h, audio and test-audio daily limits, one exit confirmation per contact, new-contacts/day hook), dedupe key per origin, reservation in `BEGIN IMMEDIATE`, `pendente` row before the connector call, `enviado`/`falhou`/`incerto` after it, `pendente` -> `incerto` on start with no automatic resend, and `reenviar` for the same row by owner action. Migration 2 adds `telefone`, `tipo`, `conteudo` and an index on `criado_em` to `envios`. New token-protected `POST /enviar` (origin fixed to `manual`); the service builds the Evolution connector from the environment when set.
- Local Evolution: `servico/evolution_local.py preparar --projeto <root>` writes `compose.yml` (from the template `servico/evolution/compose.exemplo.yml`: Evolution API v2.3.7 + Postgres 15 + Redis 7, the only published port bound to `127.0.0.1`, `host.docker.internal` mapped to the host gateway) and `.env` (0600, API key and database password generated on the spot) into the external data folder; refuses to overwrite `.env` without `--refazer`; prints the `docker compose` command and never runs Docker. The service reads the Evolution URL and key from that `.env` when the environment does not set them.
- Webhook secret mode switch: token-protected `POST /modo-webhook`; `recusa` is allowed only after 20 consecutive valid webhooks (an invalid one resets the count, both in one transaction). The screen shows the counters and a form that calls the module action `modo_webhook`, which goes through the service.
- Hardening from the review: every module action goes through `painel/modulos/vendas/cliente.py`, which reads the service port from this project's database, refuses a stale heartbeat and checks the project marker returned by `GET /saude` before asking for the token (the service records its real port and marker on start). A new or changed webhook secret resets the consecutive-valid counter and turns `recusa` back into `registra_e_conta`. `evolution_local.py preparar --refazer` keeps the Postgres password (new one only with `--senha-nova`). New deny rules for the Evolution port and `docker exec`/`inspect`/`compose config`; data-folder `Read`/`Edit`/`Write` rules anchored on the real macOS, Linux and Windows paths. A valid webhook is counted only in the transaction that stored its event. Startup notices for an incomplete or unreadable Evolution `.env` and for a missing connector. Phone numbers: leading `00` = `+`, Brazilian trunk `0` stripped, country codes starting with `0` refused. `banco.mudar_envio` changes state only from allowed source states (`enviado` is final). The data-folder hash is case-stable on case-insensitive disks.
- Receiving pipeline `servico/recebimento.py` plugged into the webhook route: dedupe by external id, groups dropped, whole-message opt-out keywords with one confirmation through the gate, 9th-digit variants, `@lid` resolution with a learned map (migration 5: `lids` table and `mensagens.envio_id`), audio/image/document and messages older than 30 min marked "precisa de você" without the AI, `fromMe` echo matching (returned id or same text within 5 s, including the echo-before-id race) and a 15-minute AI pause when the owner answers from the phone, the `ao_receber_mensagem_de_lead` hook (run after commit), and a startup fetch of what arrived while the service was down (`Conector.mensagens_desde`, Evolution `POST /chat/findMessages`). The raw webhook body is no longer stored.
- Connection tab (QR): token-protected `GET`/`POST /instancia` (`servico/instancia.py`) create or connect the instance and read state plus a fresh QR through the connector (QR never stored, never asked when connected); instance name and `numero_descartavel` live in config (not confirmed = stored false). The tab (`painel/modulos/vendas/abas/conexao.py`) shows service and Evolution state with the commands, the unofficial-connection and ban warning, the instance form, connection state, the QR in an `imagem` block and the webhook counters. New closed action `conectar_instancia`; no logout or delete anywhere.
- Conversations tab and manual sending: token-protected `GET /conversas` (list, phone masked to the last 4 digits, page limit 50, cap 100), `GET /conversas/<id>` (full phone, last 50 messages plus sends not yet echoed), `GET /incertos`, `POST /conversas/aberta` (selected conversation kept in config per project), `POST /conversas/<id>/modo` (take over / hand back to the AI), `POST /conversas/<id>/liberar` (one message to a contact who opted out, spent on the next send) and `POST /incertos/<id>/reenviar|descartar` (`servico/conversas.py`). `POST /enviar` accepts `conversa_id`: the phone comes from the conversation and the dedupe key is the screen id plus the conversation id, so the same text to another conversation is not deduped away. New `portao.descartar` (`incerto` -> `falhou`, "not sent"). The tab (`abas/conversas.py`) shows the list with badges, the `conversa` block with a send box, "Assumir a conversa" / "Devolver para a IA", the "Liberar uma mensagem" confirmation button and the uncertain sends with "Reenviar" (same row, no new key) and "Marcar como não enviada". New closed actions: `abrir_conversa`, `enviar_mensagem`, `assumir_conversa`, `devolver_ia`, `liberar_saida`, `reenviar_envio`, `descartar_envio`.
- AI brain and IA tab: `servico/cerebro.py` (+ `openai_cliente.py`, `chave.py`, `precos.py`, `ia.py`) calls OpenAI Chat Completions over urllib with a timeout and one retry, reads `error.code` from the body, never sends `reasoning_effort`, and offers four closed tools (`guardar_dado_do_lead`, `qualificar`, `enviar_link` only from the project's `links.json`, `pedir_humano`). Daily US$ cap from `usage` with a configurable price table (default US$ 2; unknown model = most expensive entry, shown on screen); cap reached, error or timeout = no call or nothing sent and "precisa de você". The key is stored only in the data folder (0600, no Keychain) and set, replaced and deleted through token-protected `/ia` routes that return only "configurada" and the last 4 characters; `GET /ia/modelos` lists the account models. New "IA" tab with the key (`segredo` field), model selector with free-text fallback, daily cap, spend and delete with confirmation. `--openai-url` / `VENDAS_OPENAI_URL` set the OpenAI base URL for tests.
- AI wired to incoming messages: `servico/atendente.py` runs the brain from the receiving hook with a 12 s per-conversation debounce, a per-conversation lock, the last 30 messages as context, the lead's text passed only as delimited data, and an injection regex that flags the conversation ("precisa de você") while still answering from the data. No write transaction during the model call; replies go through the gate with origin `ia`. Threads stop cleanly with the service. The trigger is the message id the hook handed over (a reply's `fromMe` echo no longer silences a message that arrived during the model call), and messages from a webhook with a wrong secret are stored as untrusted (`mensagens.confiavel = 0`, migration 6) and never reach the model.
- AI output sanitizer `servico/saida.py`: secrets and token-looking text never sent; tool calls written as text get one rewrite (`Cerebro.reescrever`, no tools) or nothing is sent; links outside `links.json` removed (normalized host + path, listed URL used); at most 4 sentences and 4096 characters; third near-identical reply in a row = nothing sent and "precisa de você"; up to 3 balloons through the gate with per-balloon dedupe keys and an optional `digitando` presence (new optional connector method, implemented for Evolution and the fake).
- Knowledge and tone `servico/conhecimento.py`: instructions = fixed rules + `metodos-de-venda.md` + project `oferta.md` + `tom.md` (20 KB limit each, notice on the IA tab); no `oferta.md` keeps the AI off (`sem_oferta`, no model call); the service gets the project root at start (`app.raiz`) so the tab can list what is missing; no self-introduction as assistant or AI, and a direct "are you a robot?" goes to the owner via `pedir_humano` instead of a denial; examples under `conhecimento/exemplos/`.
- AI modes per conversation (`servico/rascunhos.py`, migration 8): `rascunho` (default; the AI writes, nothing is sent) or `automatico` (origin `ia`), project default on the IA tab and an override per conversation. Drafts live in table `rascunhos`; a new lead message replaces the pending draft; the Conversas tab shows Aprovar, Editar e enviar and Descartar; approval goes through the gate with the fixed origin `rascunho_aprovado` (dedupe key = draft id, so approving twice sends once; opt-out in the meantime is denied; drafts older than 24 h expire).
- Campaign message template and disposable-number lock (`servico/modelo.py`, `servico/campanha.py`): variables `{nome}`, `{empresa}`, `{origem}` (closed list); every first message must carry the company, where the contact came from and "responda SAIR", checked at save and again on the rendered text at send time; a contact with a missing value is marked `pulado` with the reason and never sent with a blank or literal braces; max 1000 characters; links only from `links.json`. Activation (`POST /campanhas/<id>/ativar`) needs the company name (`POST /campanhas/empresa`) and, for cold contacts (base other than consentimento/cliente_existente, or never messaged), an instance created with `numero_descartavel`; the lock reads the stored config only (never the request body) and is re-checked at send time (the campaign pauses). Also `POST /campanhas` to create a draft.
- Campaign queue and scheduler (`servico/campanha.py`, `servico/agendador.py`, migration 10): campaign states `rascunho`, `ativa`, `pausada`, `concluida`; per-contact state, reason, retry time and send id; a scheduler thread that sends only through the gate with origin `campanha`, random 1.2-12 s jitter, waits on window and rate denials, warm-up curve for new contacts per day enforced inside the gate's reservation (per instance: day 1 stored in config per instance, new contact = never sent anything by this instance, `envios.instancia` column), no automatic resend of `incerto`, `falhou` retried on the same row after 60 s, restart without duplicates (the dedupe key holds), auto-pause after 5 consecutive failures, clean stop with the service. A lead who writes leaves every campaign queue. Token-protected `GET /campanhas` and `POST /campanhas/<id>/pausar|retomar`.
- Campaigns tab ("Disparos", `painel/modulos/vendas/abas/disparos.py`, service side `servico/disparos.py`): token-protected `GET /disparos` (campaigns with progress per contact state, denied/skipped reasons grouped, opted-out count, the reason a campaign paused itself, a 3-contact preview of the rendered message for drafts, today's window state and warm-up allowance used/total, company and disposable-number state), `POST /disparos/previa` and `POST /disparos/criar` (contact selection by origin / qualification / legal basis, never including opted-out contacts; shows how many are new for the warm-up and how many are cold). The tab activates (button with confirmation and the cold-contact ban warning when it applies, plus `confirmar: true` in the action data), pauses and resumes through the existing `/campanhas/<id>/...` routes; every refusal (no company, no disposable number, wrong state) is shown as an error. New closed actions: `disparos_empresa`, `disparos_previa`, `disparos_criar`, `disparos_ativar`, `disparos_pausar`, `disparos_retomar`. No phone number (not even masked) and no token in any block.
- Lead finder: example action `exemplos/acoes/vendas.json` (`vendas.buscar-leads`, niche + city, risk `credito`, locks that allow only `WebSearch`, `WebFetch` and `Write` to `<package>/dados/vendas-candidatos/`), `servico/candidatos.py` (migration 12 `candidatos`; imports and deletes each file, per-row validation, invalid files noted in `eventos` and deleted, folder outside the package or symlinked refused), import at service start, token-protected `POST /candidatos/importar` and the module action `importar_candidatos`.

- Received media (`servico/midia.py`, `servico/midia_rota.py`, migration 18 in the new `servico/migracoes.py`): lead audio, image and document get a `midias` row in the receiving transaction; after commit a bounded queue (64) and one worker download through `Conector.baixar_midia` (Evolution `POST /chat/getBase64FromMediaMessage/<instance>` with the message key, 30 s timeout, one short retry on network/5xx, 400/404/410 = expired; fake connector too), with no database transaction open and without delaying the webhook answer. Limits 16/10/20 MB; type decided by magic bytes (ogg, mp3, m4a/aac, wav; jpeg, png, webp; pdf, other documents as `application/octet-stream` with a sanitized name). Files under `<data folder>/midia/<conversation>/<random>` (0700/0600, atomic write). - AI understands lead audio and images (`servico/entender.py`, `servico/transcricao.py`, migration 19): switches "IA entende áudios" / "IA entende imagens" on the IA tab (on by default with a key; off = "precisa de você" as before) and token-protected `POST /ia/entender` (switches, transcription model, US$ per minute stored under `por_minuto` in `precos.json`). Audio: the run waits up to 20 s for the download, then `POST /v1/audio/transcriptions` (hand-built multipart, `language=pt`, `response_format=json`, one attempt, 60 s timeout) under the same daily cap (reserve in `BEGIN IMMEDIATE`, settle after); limits 5 min / 16 MB (`audio_longo`); the transcription is stored in `mensagens.transcricao`, returned by the conversation route and shown under the audio, and goes to the model as labelled delimited data. Images: jpeg/png/webp as `image_url` data URL parts with `detail: low`, max 4 and 8 MB per run, a fixed 4000 tokens per image in the worst case; HTTP 400 with an image = `modelo_sem_visao`. Documents never reach the AI (`documento_recebido`). Every failure (`transcricao_falhou`, `midia_indisponivel`, `teto_diario`, `preco_desconhecido`, ...) means no model call, nothing sent, and "precisa de você" with the reason; new reasons have pt-BR texts. `responder_em_audio` is offered in the same run as a transcribed audio.
